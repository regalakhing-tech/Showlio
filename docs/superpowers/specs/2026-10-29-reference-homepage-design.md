# Reference homepage

The owner supplied the visual design and requested a close reproduction, original generated creator/project imagery, the supplied Showlio Gradient Layered Logo, and mobile verification. Implement it in the existing PHP/Tailwind repository and preserve its GitHub/Vercel deployment workflow.

## Visual direction

Follow the supplied screenshot: white and very pale blue surfaces, cobalt blue primary actions, dark navy headings, Inter typography, soft borders/shadows, and layered slightly rotated creator cards. Preserve the section order: navigation, split hero, four steps, creator discovery, AI writing preview, featured projects, community statistics, testimonials, signup CTA and footer. Use live HTML/CSS for all UI, with generated photographs and project thumbnails as raster assets.

On small screens, use a compact accessible navigation menu, stack text and illustrations, scale the layered compositions within their containers, use two-column step/project grids where space permits and single columns on narrow screens. All controls must remain reachable without horizontal page overflow, and reduced-motion preferences must be respected.

## Behavior and scope

Navigation scrolls to sections. Search and category chips filter clearly identified sample creators. Creator/project cards open preview details; project likes/bookmarks are local browser interactions. The miniature hero UI is decorative, with full-size profile actions outside it. Testimonial controls switch the displayed sample stories. Signup opens a local profile preview, not a live account. The AI component demonstrates editable example copy and clearly labels it as a preview; it must not claim an external generation request succeeded. Sample statistics/stories are marked as illustrative content. No authentication, database or AI backend is added in this visual task.

## Verification

Run the existing syntax/build/HTTP suite, verify all local assets resolve, and inspect desktop and mobile rendering in a real browser. Check navigation, filtering, dialogs, keyboard closing and mobile menu. Keep generated assets and their prompt provenance in the project. Do not claim perfect pixel identity or live backend functionality.
